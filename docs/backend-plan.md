# Agent 用量后端开发与测试计划

用户已授权开始后端开发，并要求设计测试验证全部信息的采集正确性。当前实施目标是一个可运行的本机采集后端，提供命令行 JSON 与仅监听本机的 HTTP 接口，供后续原生菜单栏应用调用。

## 实施顺序

1. 建立统一快照、字段状态、来源、账户归属、时间范围和覆盖矩阵。未知值保留为空。
2. 复用本机 CC Switch 用量数据库；核对 4.0.5 的查询过滤、缓存语义、历史汇总和明细边界。
3. 接入 Codex 官方 app-server 的只读额度、重置卡、积分和账户 token 汇总。
4. 接入已可使用的其他来源，并为尚无登录或接口的应用返回明确的字段缺口。
5. 提供缓存、独立来源失败隔离、JSON CLI 和本地 HTTP 接口。
6. 运行离线边界测试、来源契约测试、本机真实读取和独立对账；生成验收报告。

后端先用 Python 3.9 以上标准库实现，避免开发阶段安装依赖。数据模型与传输独立于界面，后续可打包为原生应用 helper。源应用数据库只读；不执行原应用的迁移、代理接管、充值或重置卡消耗。

## 必测内容

| 信息 | 正确性验证 |
| --- | --- |
| 账户额度 | 区分已用和剩余，多个额度桶不重复统计，已超过 100% 的原值保留 |
| 重置时间 | 秒与毫秒严格区分，北京时间转换、到期重新验证，未知时间不虚构 |
| 重置卡 | 可用总数与明细分别处理，覆盖未知详情、截断明细、无卡、无期限、已过期 |
| 积分 | 单位与币种不混合，真实零、未知余额、无限额度分别表示 |
| token | 缓存包含语义、累计日志、代理与会话重复、子任务及多来源重叠 |
| 历史汇总 | 明细和旧日汇总边界、部分日期覆盖、日期筛选和源时区 |
| 估算费用 | Decimal 运算、定价缺失、倍率及估算标识，不当作账单 |
| 来源失败 | 未安装、未登录、断网、超时、schema 变化及缓存过期，不中断其他来源 |
| 接口 | 本机监听、认证、并发刷新、受控错误输出及凭据脱敏 |
| 全应用覆盖 | 每个应用逐字段报告已采集、未提供、待连接或尚不支持 |

## 验收证据

离线测试使用人工可计算的固定输入验证公式；真实测试独立查询同一只读数据库快照，并与供应方返回字段逐项比较。对尚未读到的字段，测试只验证状态和边界，不将它们计为真实接入成功。

最终交付包含运行入口、自动化测试、真实采集快照、字段覆盖矩阵和对账报告。测试结论明确区分“解析测试通过”和“本机真实数据已取得”。
