## 统计质量边界

- CC Switch 来源 schema 为 20；规则固定到 4.0.5 的上游 commit `2db86e94da13365caae55bb08d09295e31500d21`。
- 代理与会话重复使用上游 600 秒启发式规则。与其统计一致，不等于已完成所有原始请求的账单级追踪。
- 当前 30 天范围的起始日落在旧日汇总边界，不能精确还原该日部分时段；接口已标记 `partial`、`total_is_lower_bound` 和被排除日期。
- 费用保持估算标签，未定价请求与旧汇总价格完整性未知会显示为部分；不会把这些数字当作实际订阅费用。
- 未进行各原应用完整 UI 人工对账，也没有对云端其他设备的全部日志进行扫描。
- 发现规则基于已知应用名及安装包，覆盖 `/Applications` 和用户 Applications 的顶层及一层子目录，不包含任意网页、扩展和自定义安装位置。

## 交付与复现

运行方法见 [项目 README](../README.md)，字段契约见 [后端 API](backend-api.md)，机器可读结果见 测试结果（本机文件 `backend-test-results.json`，不随源码上传） 与 覆盖矩阵（本机文件 `backend-coverage.json`，不随源码上传）。

主要代码位于 `agent_meter/`，测试位于 `tests/`。验收期间实际统计快照和细项检查保存在私有 `.runtime/`。原应用数据库没有执行写入或迁移，没有消费重置卡，也没有提交模型 prompt。

下一步建议先解决 Qoder 运行时，再接入 ZCode 重置卡与 WorkBuddy/TRAE 的账户积分；已有后端接口可供菜单栏界面开发使用。
