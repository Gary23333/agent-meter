本轮已完成源码优化：限制本机日志解析缓存、减少解析与导出的临时内存、扩展两种分享海报，并修复人民币模型价格无法切换的问题。金额按用户要求统一展示人民币。当前安装版仍为原版本，本轮没有替换正在运行的应用或发布新安装包。

## 内存和刷新优化

| 路径 | 原先行为 | 本轮处理 |
| --- | --- | --- |
| Codex、Claude、Gemini、dsh、Antigravity 解析缓存 | 共用字典，但各采集器删除自己没有扫描到的文件，容易互相清空缓存 | 按来源隔离清理；共享有锁的 LRU 缓存 |
| Kimi CLI 与桌面端 | 共用解析函数与字典，两个目录互相淘汰 | 按目录区分缓存归属 |
| 日志解析结果 | 多处缓存没有明确容量边界 | 上述来源及 WorkBuddy、Qoder 共用估算 Python 对象 16 MiB、最多 512 文件的保留预算；大于预算的单项不保留 |
| Antigravity SQLite | `fetchall` 同时保留所有步骤和 generation 元数据 | 两个游标逐条配对读取，保留已有索引对应关系和异常过滤 |
| Claude 与 Gemini 去重 | 先创建全部 keyed 中间记录，再做全局去重 | 通过生成器向原有 last-wins 逻辑供给记录 |
| MiniMax Code 模型查询 | 查询结果先全部放入列表 | 游标逐条取出模型标量 |
| 分享报告 | 窗口关闭后保留 SwiftUI 视图；每次界面更新重新聚合 | 关闭释放视图；只在快照或周期变更时重建报告，模式与开关持久化 |
| PNG 导出 | 保存对话框打开前即生成图片；临时位图依赖外层自动释放 | 选择保存路径后才渲染；一次导出使用独立 autoreleasepool |

缓存淘汰只导致下次重新解析，不截断历史记录。16 MiB 是缓存对象的估算预算，不是整个后端的 RSS 限制；解析中的单个日志行、当前统计结果和 SQLite 自身内存仍独立存在。文件数很多时，有界缓存会增加重读，这是限制常驻内存的取舍。

### 可重复的压力测试

`scripts/benchmark-parser-memory.py` 生成 1,000 条虚构 Antigravity 记录，每条步骤和 generation 各含 64 KiB 无关 protobuf 字段。使用同一个 Python 3.14 解释器，通过 tracemalloc 测量解析阶段的 Python 分配。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| Python 峰值分配 | 125.445 MiB | 0.392 MiB |
| 解析耗时，单次样本 | 0.052 秒 | 0.038 秒 |
| 解析结果 | 1,000 条 | 1,000 条 |

两次结果 SHA256 完全一致。该测试证明流式读取能消除这条路径按全部元数据体积增长的峰值，不能推导为整机应用降低相同百分比。耗时仅为单次样本，未作为整体性能承诺。原始结果保存在本机忽略目录 `.runtime/performance-20261030/memory-before.json` 和 `memory-after.json`。

本轮读取到运行中旧版前端 RSS 约 184 MiB，但没有用新旧安装版做相同交互、相同后台数据的长期对照，因此没有宣称整个应用的常驻内存降幅。

| 内容 | 简洁晒用量 | 完整复盘 |

| Codex 生图 | 有数据时显示 | 有数据时显示 |

六个开关分别控制费用、缓存与构成、应用、模型、DeepSeek 峰谷、Codex 生图。切换模式恢复推荐组合；之后可自行调整，关闭窗口后仍记住选择。沿用七套主题和 1080 像素宽的 PNG 输出。

费用关闭时，主金额、模型金额、峰谷金额和生图金额一并隐藏。完整输出分项纳入账本独立提供的推理 Token；日期范围按北京时间自然日计算。只有生图记录时，Token 显示未知而不是零。

生图按本机归档文件统计，与调用次数分别展示；调用历史不可读时显示未知。生图估算标注质量假设和仅含输出，不并入 Token 费用。DeepSeek 峰谷只统计 DeepSeek 模型；无法拆分的记录单列说明，CC Switch 费用不伪造峰谷归属。

## 人民币展示与价格配置修复

界面、报告、海报、排行榜和菜单栏金额统一展示人民币。USD 按项目已有固定估算汇率 **1 USD = 7.25 CNY** 换算后汇总，并在界面及海报标明；不是实时外汇报价。Token 费用、生图费用、账户余额依然是不同指标，不能因币种相同而混成一个总量。后台原始金额和币种保留供审计。

例如 CC Switch 的 2 USD 加价格表的 3 CNY，统一显示为 17.50 CNY，不再显示两个币种，也不会只显示其中一种。

人民币单价打不开的原因是原有币种选择触发 `load()`，随后读取已保存配置又把选择还原成 USD。修复后：

- `GET /v1/prices/USD` 和 `/v1/prices/CNY` 提供只读预览，原 `GET /v1/prices` 保持兼容。
- 预览重建所选币种的内置及目录价格；已有自定义单价按固定汇率换算。查看不写磁盘，保存后才生效。
- 配置窗口通过 NSHostingController 挂载，减少原生控件接收点击异常；切换币种不再循环触发重载，同一窗口内保留各币种草稿。
- 保存仅写已存在的用户覆盖及本次修改的单价；同步目录模型的编辑不再被忽略，未修改的目录价也不会被全部冻结成自定义覆盖。
- 非法单价拒绝保存，避免将输错的文本默认为免费价格。

前后端需要一起更新；旧版后端没有这两个币种预览端点。

## 下一步功能优先级

### 优先做 预算和异常消耗提醒

用户填写日/周预算，在估算费用超过阈值或消耗速度异常时提醒，并能定位到应用和模型。现有额度提醒关注账户余量，这个功能回答“今天为什么突然花得多”。优先支持本机 API 等价预算，明确与实际扣费分开；提醒需要基于完整时间窗，并对采集恢复产生的补记去重。

### 其次做 按项目归因

把用量分到本机工作目录或用户命名的项目，支持查看项目的应用、模型和费用。先接入能明确提供项目路径或 session 映射的来源，其余进入“未归属”，不从对话正文猜项目。项目路径可能敏感，分享默认只使用用户起的别名。

### 随后做 周报和环比

增加自然周/月与上一周期对比、费用变化主要来源、缓存效率变化，并复用本轮完整复盘海报。当前账本只输出滚动 7/30 日聚合，前一周期需要后端补齐同口径日汇总，不能拿滚动 7 日与自然周直接对比。

### 同步考虑 数据状态面板和省资源模式

数据状态面板显示最近成功采集时间、来源故障、未计价模型、未归属记录与估算口径；省资源模式可降低后台采集频率，并按来源选择是否读取较大的历史库。这样用户能解释“为什么今天少算了”和“哪个来源耗资源”，也能验证下一轮性能优化。

这些优先级基于当前软件已有能力与缺口。作为外部对照，[ccusage 官方说明](https://ccusage.com/guide/)已经将日、周、月和会话维度列为基础分析视图；[CodexBar 的 Codex 数据说明](https://github.com/steipete/CodexBar/blob/main/docs/codex.md)也强调账户额度与本机成本覆盖不同。这些资料支持完善归因和时间维度，但不表示本项目已经实现这些建议。
