# AgentMeter 0.10.4

2026 年 11 月 10 日。本版把 5 小时 / 7 天额度卡从「窗口重置才结算」改成「越档即掉落」，并据此重写了 README 与全部演示截图。其余功能与统计口径不变。

## 额度卡改为实时发卡（新）

- **规则**：5 小时 / 7 天窗口的用量每越过一档（50% / 80% / 90% / 用满）就**立刻**掉一张卡，不用等窗口重置；同一窗口同一档只掉一张，峰值后续继续上涨就再补下一档。一个冲到 100% 的窗口最多出四张（普通 / 稀有 / 史诗 / 传说各一）。
- **时间戳**：掉卡时间记为「该档位被观测到的时刻」。本次采样抬高了峰值就用当前时间，峰值未再上涨则沿用上一次观测时间——因此「最近掉落」列表反映的是真实越过档位的时刻，而不是窗口结束时刻。
- **窗口结算退化为兜底**：窗口结束（读到新的 `resets_at`，或来源消失且重置已过 1 天）时结算，只补发尚未掉过的档位。`stale`、`error` 来源依旧不参与；低于 50% 不掉卡。
- **升级行为**：升级前就存在的窗口（账本里没有掉档记录）会在下一次采集时按新规则**一次补齐所有越过的档**，时间戳记为上次观测到该峰值的时候。因此升级瞬间可能会集中收到几张卡。
- **面板同步**：「冲刺中」区块的「已锁定」改为「已获得」，并显示本窗已掉落的张数；倒计时由「X 后结算」改为「X 后重置」（窗口仍会重置，只是不再承担发卡职责）。

## 卡片张数不再随掉落日志缩水（新）

- 掉落日志只保留最近 3000 条，而发卡变多后更早触顶，裁掉最旧的掉落会让老卡的「×N」慢慢变小。
- 现在每张卡的**张数 / 首次获得 / 最近获得 / 来源**单独记在账本的 `cards` 台账里，收集册的计数以台账为准，掉落日志只负责「最近掉落」。旧账本首次读取时自动从已有日志回填台账，不会丢张数。

## README 重写与截图重生成

- README 按 v0.10.4 的实际代码彻底重写：更新徽章版本号、安装步骤（不再停留在 v0.9.9）、数据源矩阵（补齐本机账本与账户来源）、补上 v0.10.0 – v0.10.3 的更新日志，并把「收集册」补成正式的一节。
- 全部演示截图用当前代码重新生成（账户额度、本机消耗、应用页、重置预测、行情条、七套主题对比、分享卡），新增收集册页与桌宠页截图。演示数据仍为虚构，不含任何真实账户信息。

## 与既有版本的关系

v0.10.3 的 Qoder 每日活动积分、v0.10.2 的积分签到与集卡、v0.10.1 的桌宠系统、本机消耗口径全部不变。本版只改额度卡的掉落时机与计数方式，不改任何采集逻辑、接口契约或统计口径。

## 验证

- Python 回归 666 项全过（Python 3.14），Swift 测试 74 项全过。
- 端到端跑通 `SnapshotService`：用量 40% → 62% → 85% → 97%，`open_windows[].granted` 依次为 `[]` → `[q5_50]` → `[q5_50, q5_80]` → `[q5_50, q5_80, q5_90]`，收集册张数同步增长，「最近掉落」即时出现。
- 旧账本迁移用一份仿 schema-1 账本验证：台账从日志回填正确，张数与首次获得时间不变。
